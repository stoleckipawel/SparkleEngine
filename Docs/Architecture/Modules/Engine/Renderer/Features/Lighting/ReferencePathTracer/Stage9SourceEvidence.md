## Delivered Source Route

The original frame remains the only producer of viewport products. Lit and Reference middles publish the producer-neutral `Radiance` product, while Reference additionally publishes optional `RadianceSecondMoment` and an exact `RenderProductSamplePrefix`. `ViewportCaptureService` resolves them through the existing generic asynchronous RHI texture-readback service. Each manual workflow retains and polls the exact generic Renderer ticket it requested, so `EditorApplication` does not drain an anonymous queue or dispatch payloads by feature. A progressive capture snapshots the SHA-256 render identity, committed sample count, and target sample count. Capture requests/results are destination-free: output paths, codecs, staging, and publication never cross Renderer or RHI. No Reference-specific RHI method, capture pass, AOV, counter stream, event stream, detached renderer, or command-line render mode remains.

The shared private `ViewportCaptureSlot` is now the sole Application owner of an admitted ticket's request/poll/readback/discard settlement. Ordinary viewport capture owns one slot and Reference artifact publication composes two for mean/M2; neither coordinator carries a parallel ticket, abandoned-ticket list, optional delivery state, or polling loop. `EditorOperationSlot` similarly owns task occupancy and the unconsumed terminal result, preventing a new launch from replacing settled work; Reference publication and shader recook carry no duplicate active flag.

The final graph-composition refinement removed the forwarding `SceneRenderStage` and `ReferencePathTracer` classes. `FramePipeline` owns the persistent `ReferencePathTracerSession` lifetime and its narrow preparation/submission calls, while the ordinary `AddSceneRenderingPasses` function owns the sole Lit-versus-Reference graph decision and directly invokes either `AddRealTimePathTracerPasses` or `AddReferencePathTracerPasses`. Shared exposure, optional scene denoising, and selected presentation upscaling are declared in order outside both branches. `EditorApplication` owns one `EditorViewportOutputCoordinator` rather than ordinary-capture and Reference-artifact coordinators. `EditorApplicationLaunch` is again a single interactive host entry with no feature dispatch. These are explicit composition seams, not registries, class-shaped graph stages, forwarding feature facades, recipe hierarchies, dependency bags, service locators, or RHI extensions.

`ApplicationEditor` owns the rest of the workflow. Reusable mechanism lives under `Private/Editor/Capture` and `Private/Editor/Artifacts`; Reference-only intent and schema remain under `Private/Editor/ReferencePathTracer`:

- `ReferencePathTracerArtifactCoordinator` consumes semantic artifact kinds, binds each explicit button request to one session identity, turns current-prefix/checkpoint requests into pause-and-settle intents, and starts generic readback only after the existing session reports a stable paused or completed prefix. Public Editor UI emits one generic viewport-output action and `ReferencePathTracerArtifactActions` translates it once; no deferred save intent remains;
- `ImageEncoding` consumes a generic image-buffer view and is the one private Application owner for BMP/EXR codecs and pixel conversion; it has no viewport, session, or Reference semantics. `ArtifactBundlePublication` is the one private owner for contained, budgeted, hash-verified, completion-file-last, same-volume atomic directory publication. `ReferencePathTracerArtifactEncoding` owns only the FLOAT RGB output choice plus the frozen little-endian mean/M2/count checkpoint and canonical manifest schemas; `ReferencePathTracerArtifactWriter` is the thin feature composition that describes those files to the shared publisher;
- output stays under an explicit writable root, never overwrites an existing publication, refuses insufficient disk/budget, rejects a readback whose exact provenance changed after intent capture, rejects cross-digest checkpoint planes, removes only staging created by the current transaction, responds to task cancellation between encoding/publication stages, and leaves the live GPU prefix plus earlier or foreign publications untouched;
- the Editor's collapsed `Evidence / Output` surface issues artifact intent only; it does not own Renderer state or filesystem/codec policy;
The refinement audit removed host/UI identity from the transport digest: the View component contains the transport-relevant render extent, while `viewportId` remains solely in the session's ownership/action routing. Editor `Scene` and runtime `Game` producers therefore do not fork digest or sample identity merely because their host or viewport owner differs. Shared SHA-256 hex formatting and root-containment policy remain in Core; no feature-prefixed copy of either mechanism remains.

The 2026-09-19 manual-only clean break deletes `EditorToolCommandLine`, the Reference command adapter, hidden render loop, request/manifest parser, command switch, JSON-lines protocol, and stable process-exit contract. Generic Renderer/RHI capture, manual viewport output actions, ApplicationEditor encoding, checkpoint/manifest schemas, and atomic publication remain.
